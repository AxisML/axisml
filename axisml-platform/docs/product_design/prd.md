# AxisML 产品需求说明文档（PRD）

## 1. 概述

**AxisML** 是一款 AI 训练推理一体的一站式机器学习平台，覆盖模型开发、训练、制品管理、在线推理与系统运维。本文档从用户视角描述目标用户、核心概念与功能能力（"为谁做、做什么"）；架构与实现取舍见 [概要设计](../../../docs/high_level_design.md)，字段级契约以 [docs/system_design/](../system_design) 与 [openapi/](../apis) 为准。

页面布局与交互以 [交互原型 prototype/](prototype) 为权威。

## 2. 目标用户与角色

平台按三种角色区分菜单可见性与写权限，每个功能小节注明可见角色：

- **系统管理员**（`system-admin`）：平台超管。开通 / 停用 / 删除租户，分配租户初始配额，上下线资源池与维护资源单元；可见"系统管理"全部入口。
- **租户管理员**（`tenant-admin`）：单租户负责人。在系统管理员分配的额度内拆分本租户配额、管理成员；不可跨租户操作。
- **普通用户**（`user`）：算法工程师 / 数据科学家 / 推理运维等业务使用者。在所属租户内用工作区、跑任务 / 实验、部署服务、管理制品。

## 3. 核心概念

| 术语 | 一句话解释 | 用户最常见动作 |
| --- | --- | --- |
| 租户 Tenant | 业务 / 团队接入平台的开通单位，决定配额边界与命名空间 | 系统管理员开通；租户管理员维护成员与配额 |
| 资源池 ResourcePool | 管理员预划的算力分组（如 A100 训练池、CPU 通用池） | 提交任务 / 服务时选择 |
| 资源单元 ResourceUnit | 资源池内的规格档位（如 `a100-1x-large`） | 提交时从下拉选档位，不手填资源量 |
| 资源配额 Quota | 租户在某资源池下分配的"资源单元 × 数量" | 系统 / 租户管理员设置；用户查看 |
| 数据卷 DataVolume | 平台级持久存储卷（K8s PVC），由系统管理员为租户预建，供工作区 / 任务 / 实验挂载 | 系统管理员创建 / 删除；用户提交时挂载 |
| 工作区 Workspace | 交互式开发容器（Jupyter / VSCode），用完即停 | 按需启动、调试、停止 |
| 任务 Job → 运行 Run | 一次性 workload（训练 / 微调 / 数据处理）；Job 是可复用模板，每次运行生成一个 Run | 提交、触发运行、看日志、取产物 |
| 实验 Experiment | 训练特化任务；把同一目标的多次 Run 归并，经 TensorBoard 看指标与对比 | 多次运行、对比、登记模型 |
| 服务 Service | 长驻在线推理 workload，可扩缩容 | 上线、扩缩容、停止 / 下线 |
| 流量策略 Traffic Policy | 把一个稳定入口的流量按权重 / 灰度分发到多个在线服务 | 灰度放量、加权切分、提升 / 回滚 |
| 制品 Artifact | 模型 / 镜像等可复用资产，按版本引用 | 注册、维护版本、按版本引用 |

> **任务与实验同构**：二者都是"定义（模板）→ 运行（Run）"两级模型，训练超参即命令 / 参数 / 环境变量，平台不单独建模。实验额外提供 TensorBoard 指标查看与多 Run 对比。

## 4. 功能地图与角色可见性

| 一级菜单 | 二级菜单 | system-admin | tenant-admin | user |
| --- | --- | :---: | :---: | :---: |
| 首页 | — | ✅ | ✅ | ✅ |
| 训练中心 | 工作区 / 自定义任务 / 实验 | ✅ | ✅ | ✅ |
| 服务中心 | 在线服务 / 流量配置 | ✅ | ✅ | ✅ |
| 资产中心 | 模型 / 镜像 | ✅ | ✅ | ✅ |
| 系统管理 | 租户管理 | ✅ | 部分（仅本租户配额 / 成员） | ❌ |
| 系统管理 | 资源池管理 | ✅ | ❌ | ❌ |
| 系统管理 | 数据卷管理 | ✅ | ❌ | ❌ |

租户内菜单（工作区 / 任务 / 实验 / 服务 / 流量 / 制品）的作用域由顶部"所属租户"切换器决定。

## 5. 功能详述

每个功能描述：**做什么 / 典型操作 / 输入 / 输出 / 关系**。

### 5.1 首页（Dashboard）

按"所属租户"作用域呈现概览与快捷入口。

- **租户视图**（全角色）：当前"所属租户"的活跃任务 / 在线服务 / 工作区 / 模型 KPI、配额水位（GPU / CPU / 内存）、用量趋势图、快捷新建入口。
- **集群容量**（仅 system-admin）：集群容量水位作为系统管理员看板呈现，属全集群信息，不依赖任何租户作用域选择。
- **关系**：所有菜单的导航起点。

### 5.2 训练中心

#### 工作区

- **做什么**：申请交互式开发环境（Jupyter / VSCode），调试代码与试跑小实验。
- **典型操作**：选镜像与资源单元 → 挂载数据卷 → 启动 → 浏览器进 IDE → 不用时停止。
- **输入**：镜像、资源单元、数据卷、环境变量。**输出**：开发环境 URL，工作目录持久化。
- **关系**：脚本稳定后通过"自定义任务"提交正式训练。

#### 自定义任务

- **做什么**：提交一次性训练 / 微调 / 数据处理任务，支持单机与分布式；Job 模板可复用，每次运行生成一个 Run。
- **典型操作**：填模板（名称 / 镜像 / 资源池 / 资源单元 / 副本数 / 启动命令 / 环境变量 / 数据卷）→ 保存 → 触发运行（可本次覆盖镜像 / 资源 / 超参）→ 在 Run 详情看日志、实例、事件 → 产出可注册为模型。
- **输入**：镜像、资源单元、命令与参数、数据卷、副本数、运行策略（超时 / 重试）。**输出**：Run 状态 / 日志 / 产出文件。
- **关系**：消费"镜像"；产出写回"模型"；受租户配额约束。

#### 实验

- **做什么**：训练特化任务，把同一目标的多次 Run 归并管理，经 TensorBoard 看训练指标与多 Run 对比，并将满意的运行登记为模型。与"自定义任务"同构（模板 → Run），命令含可覆盖的超参模板变量（如 `{{lr}}`）。
- **典型操作**：建实验模板 → 以不同超参多次触发运行 → 启动 TensorBoard 对比各 Run → 选定运行，一键登记 checkpoint 为模型版本。
- **输入**：镜像、资源单元、分布式拓扑、命令与参数（超参）、数据卷。**输出**：各 Run 状态 / 日志、TensorBoard 指标对比、可登记的模型产出。
- **关系**：与"自定义任务"共享 Job → Run 模型；最佳产出写回"模型"；受租户配额约束。

### 5.3 服务中心

#### 在线服务

- **做什么**：将模型版本部署为长驻推理服务，对外提供 HTTP/gRPC。
- **典型操作**：选模型版本与推理镜像 → 选资源单元与副本数 → 配端口与路由 → 上线 → 看监控（QPS / 延迟 / 错误率）→ 扩缩容、停止 / 启动、删除。
- **输入**：模型版本、镜像、资源单元、副本数、端口、路由。**输出**：服务端点、运行指标与日志。
- **关系**：消费"模型"；多版本灰度由"流量配置"承接；受租户配额约束。

#### 流量配置

- **做什么**：为在线服务做多版本流量编排——一个稳定入口按权重 / 灰度分发到多个服务后端，支持灰度放量、提升 / 回滚。
- **典型操作**：建策略 → 选模式（加权 / 灰度）→ 绑定后端服务并设权重 / 灰度百分比 → 上线 → 对比各后端 QPS / 延迟 / 错误率 → 放量或提升 / 回滚。
- **输入**：对外入口（path / hostname）、后端服务集合与权重 / 灰度百分比。**输出**：统一服务端点、各后端实时流量与健康对比。
- **关系**：消费"在线服务"作为后端；配合"模型"版本迭代做灰度。

### 5.4 资产中心

模型与镜像共用同一套"制品 + 版本"模型：制品身份为 `(租户, 类型, 名称, 版本)`，同名制品下挂多个版本，按 `name@version` 引用。

#### 模型

- **做什么**：注册模型、维护版本、检索与引用。
- **典型操作**：从训练产出一键注册 / 手动上传外部模型 → 维护标签与说明 → 在任务或在线服务中按版本引用。版本可通过 Web 上传 / ORAS 推送 / 远端登记加入。
- **关系**："自定义任务 / 实验"的产出来源；"在线服务"的输入。

#### 镜像

- **做什么**：登记训练 / 推理 / 开发镜像，统一在工作区、任务、服务中按版本引用。
- **典型操作**：本机 docker push / 远端登记镜像版本 → 维护用途（training / inference / dev）与说明 → 提交时下拉选择。
- **关系**：被"工作区 / 自定义任务 / 实验 / 在线服务"消费。

### 5.5 系统管理

#### 租户管理

- **可见角色**：系统管理员（完整）；租户管理员（仅本租户配额与成员）。
- **做什么**：系统管理员创建 / 停用 / 启用 / 删除租户，设初始配额；租户管理员在额度内拆分配额、管理成员。
- **典型操作**：填租户名称 / 租户 ID / 初始管理员邮箱 → 按资源池分配各资源单元的数量 → 提交；后续调整配额、增删成员、停用 / 启用。
- **输入**：租户标识、各资源池下的"资源单元 × 数量"、成员与角色。**输出**：租户开通状态、底层命名空间与初始资源就绪、配额用量。
- **关系**：约束训练 / 服务中心所有任务 / 服务的可调度容量。

#### 资源池管理

- **可见角色**：系统管理员。
- **做什么**：定义资源池的节点选择条件与可选容量覆盖；在池下维护资源单元规格档位；上线 / 下线池。
- **典型操作**：新建资源池 → 设节点 label 匹配，必要时覆盖计算容量 → 在池下定义若干资源单元（requests / limits）→ 上线 → 在租户管理中按池分配配额。
- **输入**：节点选择规则、可选 capacity、资源单元规格列表。**输出**：可用资源池与资源单元目录，供配额分配与提交时选择。
- **关系**：是"租户配额"的承载维度，也是训练 / 服务中心的资源选择来源。

#### 数据卷管理

- **可见角色**：系统管理员。
- **做什么**：为租户预建 / 删除持久数据卷（K8s PVC），统一供工作区、自定义任务与实验挂载持久存储；查看卷的容量、访问模式与挂载占用，删除前做占用校验。
- **典型操作**：在"所属租户"作用域下新建数据卷（名称 / 容量 / 存储类 / 访问模式 / 描述）→ 等待供给就绪（Pending → Bound）→ 用户在工作区 / 任务 / 实验提交时按名称挂载到指定路径 → 查看卷状态与占用工作负载 → 不再使用时删除（被占用则阻止并列出占用方）。
- **输入**：数据卷名称、容量、存储类（StorageClass）、访问模式（RWO 单节点读写 / RWX 多节点读写 / ROX 多节点只读）、描述。**输出**：卷状态（Pending / Bound / 异常）、绑定容量、占用该卷的工作负载列表、可供挂载的卷引用。
- **关系**：作用域随顶部"所属租户"切换器，卷归属单一租户命名空间；被"工作区 / 自定义任务 / 实验"挂载消费；与"数据集"制品相互独立——卷是非结构化读写挂载，数据集是版本化只读产物。

## 6. 多语言（国际化）

平台前端面向用户的界面是多语言的，作为贯穿所有功能的横切能力。

- **语言范围**：首批简体中文与英文，按可扩展设计，后续增补语言不改动既有功能。
- **本地化范围**：覆盖全部菜单、列表 / 详情 / 表单文案、按钮、状态标签、提示与错误；日期 / 数字 / 时区按所选语言呈现。用户自有自由文本（显示名 / 描述 / 标签等）按原文存储与展示，不翻译。
- **切换与记忆**：入口在顶部用户菜单，默认随浏览器语言，即时生效并在本浏览器记住。
- **实现取向**：多语言是前端职责，后端与下游服务语言中立（只返回稳定机读错误码），契约见 [platform.md §5.6](../system_design/backend.md#56-多语言--i18n)。

## 7. 范围外与后续工作

- **数据集**与**评估**：作为制品与训练能力的自然延伸，本期不交付独立菜单与页面（任务 / 实验当前以数据卷形式挂载数据）；系统设计已为数据集制品保留底层 kind，后续迭代再补产品形态。
- 特征平台、向量检索、模型定制。
- 数据卷的存储配额与自动回收 / 生命周期策略（容量配额计入租户、TTL 到期回收、快照 / 克隆）；本期数据卷管理提供创建 / 删除 / 挂载与占用校验，配额与回收策略后续迭代。
- 多集群联邦、跨地域部署；计费 / 账单 / 计量。

# AxisML 产品需求说明文档（PRD）

## 1. 概述

**AxisML** 是一款 AI 训练推理一体的一站式机器学习平台，覆盖模型开发、训练、制品管理、在线推理与系统运维。本文档从产品视角描述平台的目标用户、核心概念、典型场景与功能能力，回答"为谁做、做什么"。

本文档与 [概要设计文档](../system_design/overview.md) 互补：

- **PRD（本文档）**：站在用户视角描述能力边界与使用方式；面向产品、业务、解决方案等读者。
- **概要设计**：站在工程视角描述架构与实现取舍；面向研发与运维。

字段级 schema、CRD 与组件契约以 [docs/system_design/](../system_design/) 下的详细设计为准。

## 2. 目标用户与角色

平台只区分三种角色，对应不同的菜单可见性与操作权限：

- **系统管理员**：平台级超管。负责租户的创建 / 暂停 / 恢复 / 删除，资源池上线下线与资源单元规格维护，平台级数据卷管理；可见"系统管理"全部入口。
- **租户管理员**：单个租户内的负责人。负责本租户在各资源池下的配额分配与调整，组织工作区成员；可见本租户范围内的管理能力，无法跨租户操作。
- **普通用户**：算法工程师、数据科学家、推理服务运维等业务使用者的统称。在所属租户与工作区内使用工作区、提交训练任务、部署在线服务、注册和消费制品。

每个功能小节会注明该功能对哪些角色可见、谁能写入。

## 3. 核心概念

为方便理解后续功能描述，下表用产品语言重述了平台的关键概念。完整定义与字段语义见 [概要设计 §2](../system_design/overview.md#2-核心概念)。

### 3.1 概念释义

- **租户（Tenant）**：业务/团队接入平台的最小开通单位，决定了可用的配额边界与资源命名空间。系统管理员开通租户、设定初始配额；租户管理员在租户内继续拆分。
- **工作区（Workspace）**：用户在平台上看到的工作容器，是任务、服务、制品的归属单位。一个租户可对应一个或多个工作区。
- **资源池（ResourcePool）**：管理员预先划分的算力分组，例如"A100 训练池""H100 推理池""通用 CPU 池"。普通用户提交任务/服务时选择落在哪个池。
- **资源单元（ResourceUnit）**：资源池内预设的规格档位（例如 `a100-1x-large` = 1×A100 + 8 vCPU + 32 GiB）。普通用户不直接填资源数字，而是从下拉菜单中选档位。
- **资源配额（Quota）**：某个租户在某个资源池下可用额度（min/max 二维）。决定该租户能并发跑多少任务/服务，超出 max 时新任务会等待。
- **计算负载（Compute Workload）**：任务和服务的统称。
- **任务（Job）**：一次性运行直至完成或失败的 workload，典型用途是训练、微调与离线数据处理。
- **服务（Service）**：长驻运行、对外提供推理的 workload，可按副本数扩缩容。
- **制品（Artifact）**：模型、镜像、数据集等可复用资产的统一抽象。普通用户在制品中心注册和检索，在任务/服务中按版本引用。

### 3.2 概念速查表

| 术语 | 一句话解释 | 用户最常见动作 |
| --- | --- | --- |
| 租户 | 业务/团队的接入单位 | 系统管理员创建；租户管理员维护 |
| 工作区 | 用户操作的容器视图 | 普通用户登录后默认进入 |
| 资源池 | 管理员预分的算力分组 | 普通用户在提交任务时选择 |
| 资源单元 | 资源规格档位 | 普通用户在提交任务时选择 |
| 资源配额 | 租户可用额度 | 系统/租户管理员设置；普通用户查看 |
| 任务 | 一次性 workload | 普通用户提交、查看日志、取产物 |
| 服务 | 长驻在线推理 | 普通用户上线、扩缩容、灰度更新 |
| 制品 | 可复用资产（模型/镜像/数据集） | 普通用户注册、按版本引用 |

## 4. 典型使用场景

### S1 开通租户与初始配额（系统管理员）

新业务线接入：系统管理员在"租户管理"中创建租户，为其在相关资源池下设置初始 min/max 配额；平台自动初始化租户的 Namespace、Secret、ServiceAccount 等基础资源。

### S2 租户内拆分配额（租户管理员）

租户管理员登录后只看到本租户。将租户在某个资源池下的总额度按团队拆分（例如训练团队 70%、推理团队 30%），并能随业务节奏调整。

### S3 提交一次训练任务（普通用户）

算法工程师在"自定义任务"中：选择资源池与资源单元 → 选择训练镜像 → 配置启动命令与超参 → 选择数据卷挂载 → 提交。任务运行期间可在任务详情查看日志、指标、节点分布；运行结束后产出模型可一键注册到制品中心。

### S4 部署在线推理服务（普通用户）

推理服务运维在"在线服务"中：从制品中心选择已注册的模型版本 → 选择资源单元与副本数 → 配置健康检查与服务路由 → 上线。服务运行后可手动扩缩容、灰度切换模型版本、下线旧版本。

### S5 制品消费链路（普通用户）

工程师将训练产出的模型注册为新版本 → 在新一次实验或在线服务中按 `name@version` 引用；同样可登记自定义训练镜像或推理镜像，统一在任务/服务中按版本调用。

### S6 资源池上线（系统管理员）

集群新增 H100 节点：系统管理员定义新的资源池（节点选择条件、容忍配置）、维护其下若干资源单元规格档位，上线后即可暴露给租户使用。

## 6. 功能详述

每个功能统一描述：**可见角色 / 能做什么 / 典型操作 / 输入 / 输出 / 与其他功能的关系**。

### 6.0 角色与菜单可见性矩阵

| 一级菜单 | 二级 | 系统管理员 | 租户管理员 | 普通用户 |
| --- | --- | :---: | :---: | :---: |
| 首页 | — | ✅ | ✅ | ✅ |
| 训练 & 推理 | 工作区 / 自定义任务 / 在线服务 | ✅ | ✅ | ✅ |
| 制品中心 | 模型 / 镜像 | ✅ | ✅ | ✅ |
| 系统管理 | 租户管理 | ✅ | 部分（仅本租户配额） | ❌ |
| 系统管理 | 资源池管理 | ✅ | ❌ | ❌ |
| 系统管理 | 数据卷管理 | ✅ | ❌ | ❌ |

### 6.1 首页

- **可见角色**：全部。
- **能做什么**：登录后默认落地页，呈现当前工作区与租户的整体态势与快捷入口。
- **典型操作**：浏览概览卡片、跳转到具体任务/服务/制品详情、跳转到管理入口。
- **输入**：当前用户身份与所属租户/工作区。
- **输出**：
  - 普通用户：本工作区近期任务/服务状态、配额使用、收藏的制品、快捷新建入口。
  - 租户管理员：在普通用户视图基础上，叠加租户级配额水位、成员资源使用排行。
  - 系统管理员：平台级概览——租户数、资源池水位、在线服务总量、近期异常告警。
- **关系**：所有其它菜单的导航起点。

### 6.2 训练 & 推理

#### 6.2.1 工作区

- **可见角色**：普通用户（租户管理员、系统管理员同样可使用）。
- **能做什么**：申请交互式开发环境（如 Jupyter / VSCode Web），用于代码调试和小规模实验。
- **典型操作**：选择镜像与资源单元 → 选择需要挂载的数据卷与制品 → 启动 → 通过浏览器进入 IDE → 不用时停止释放资源。
- **输入**：镜像（来自镜像中心）、资源单元、数据卷挂载、可选的初始化脚本。
- **输出**：可访问的开发环境 URL；环境内的工作目录可持久化。
- **关系**：常作为编写训练脚本、试跑代码的起点；脚本稳定后通过"自定义任务"提交正式训练。

#### 6.2.2 自定义任务

- **可见角色**：普通用户。
- **能做什么**：提交一次性训练 / 微调 / 数据处理任务，支持单机和分布式（多机多卡）。
- **典型操作**：填写任务名 → 选择资源池与资源单元、副本数、并行策略 → 选择训练镜像 → 配置启动命令、环境变量、超参 → 挂载数据卷与依赖制品 → 提交 → 在任务详情查看日志、指标、Pod 分布 → 任务结束后可将产出注册为模型版本。
- **输入**：镜像、资源单元、命令与参数、数据卷与制品引用、副本数。
- **输出**：任务运行状态与日志、指标、产出文件；可注册为模型制品版本。
- **关系**：消费"镜像""数据卷"作为输入；产出可写回"模型"；运行受"租户管理"中配额约束。

#### 6.2.3 在线服务

- **可见角色**：普通用户。
- **能做什么**：将已注册的模型版本部署为长驻推理服务，对外提供 HTTP/gRPC 接口。
- **典型操作**：选择模型版本 → 选择资源单元与副本数 → 配置健康检查、超时、路由前缀 → 上线 → 在服务详情查看流量、延迟、错误率 → 扩缩容、切换模型版本、下线。
- **输入**：模型制品版本、资源单元、副本数、路由配置。
- **输出**：可调用的服务端点；运行指标与日志。
- **关系**：消费"模型"作为输入；流量由平台基础设施统一接入；运行受"租户管理"中配额约束。

### 6.3 制品中心

#### 6.3.1 模型

- **可见角色**：普通用户。
- **能做什么**：注册模型、维护版本、检索与引用。
- **典型操作**：从训练任务一键注册产出 → 也可手动上传外部模型 → 维护版本说明、标签、关联实验 → 在任务或在线服务中按 `name@version` 引用。
- **输入**：模型文件（来自训练产出或本地上传）、元数据（版本、标签、说明）。
- **输出**：不可变的模型版本引用；版本列表与详情。
- **关系**："自定义任务"的产出来源；"在线服务"与下一次"自定义任务"的输入。

#### 6.3.2 镜像

- **可见角色**：普通用户。
- **能做什么**：登记训练 / 推理镜像，统一在任务、服务、工作区中按版本引用。
- **典型操作**：登记内部构建的镜像版本（或引用外部仓库）→ 维护标签与说明 → 在提交任务/服务/工作区时下拉选择。
- **输入**：镜像引用（地址 + tag/digest）、元数据。
- **输出**：版本化的镜像条目，供任务、服务、工作区引用。
- **关系**：被"工作区""自定义任务""在线服务"消费。

### 6.4 系统管理

#### 6.4.1 租户管理

- **可见角色**：
  - 系统管理员：完整能力。
  - 租户管理员：仅本租户的配额视图与调整。
- **能做什么**：
  - 系统管理员：创建 / 暂停 / 恢复 / 删除租户；为租户在各资源池下设置初始配额；查看配额使用回流。
  - 租户管理员：在系统管理员设定的总额度内，进一步拆分本租户在各资源池下的配额。
- **典型操作**：填写租户基本信息 → 选择资源池并设置 min/max 配额 → 提交；后续按需调整配额或暂停/恢复。
- **输入**：租户标识、所在资源池、min/max 配额。
- **输出**：租户开通状态、底层 Namespace 与初始资源就绪状态、配额使用率回流。
- **关系**：约束"训练 & 推理"下所有任务/服务的可调度容量。

#### 6.4.2 资源池管理

- **可见角色**：系统管理员。
- **能做什么**：定义资源池的节点选择条件与容忍配置；维护池下的资源单元规格档位；上线 / 下线池。
- **典型操作**：新建资源池 → 设置节点 label/taint 匹配 → 在池下定义若干资源单元（如 `a100-1x` / `a100-4x` / `cpu-medium`）→ 上线 → 在租户管理中按池分配配额。
- **输入**：节点选择规则、资源单元规格列表。
- **输出**：可用资源池与资源单元目录，供"租户管理"分配配额、供普通用户在提交任务/服务时选择。
- **关系**：是"租户管理"配额的承载维度，也是"训练 & 推理"所有功能的资源选择来源。

#### 6.4.3 数据卷管理

- **可见角色**：系统管理员。
- **能做什么**：维护平台级数据卷的注册、容量规划与回收策略，供租户在任务、服务、工作区中挂载使用。
- **典型操作**：登记新数据卷（对象存储桶、共享存储路径等）→ 设置访问策略与配额 → 暴露给租户 → 必要时回收。
- **输入**：存储后端连接信息、容量规划、可见租户范围。
- **输出**：可被普通用户在挂载下拉中看到的数据卷目录。
- **关系**：被"工作区""自定义任务""在线服务"挂载使用。
- **状态**：能力规划中（[overview §3](../system_design/overview.md#3-功能矩阵) 标记为 TBD），本节仅定义产品形态，落地细节随后续设计补充。

## 7. 范围外（Out of Scope）

本期 PRD 不承诺以下能力：

- 实验跟踪、特征平台、向量检索、模型评测平台。
- 数据集制品、模型定制（[overview §3](../system_design/overview.md#3-功能矩阵) 标记为 TBD 的能力暂不进入 PRD；数据卷管理虽也为 TBD，但作为系统管理菜单项纳入 §6.4.3）。
- 多集群联邦、跨地域部署。
- 计费 / 账单 / 计量上报。
